### B01 · P2 · 竞技观战名册刷新会丢失键盘焦点

- 位置：`dist/js/hud.js:142`、`dist/js/app.js:97`、`dist/js/overlays.js:303`。
- 经典远程／近战刀战死亡后，存活角色行获得 `role="button" tabindex="0"`，但 HUD 约每 100ms 无条件重写整份 `roster.innerHTML`。聚焦的旧行会被移除，新行没有继承焦点，Enter／Space 无法继续在原行触发选人。
- 补充探针调用真实 `createHud().update()`，模拟 DOM 子树替换时的焦点语义；即使对局状态完全不变，两武器下第二次刷新也都断开旧焦点节点并回到 body。另一路真实入口 mock 探针也复现了刷新后按键未切换目标。未做真实浏览器复核。
- 首领榜单已按角色复用节点并恢复焦点，竞技名册没有相应处理。
- 建议：复用角色节点，或记录并按角色 ID 恢复焦点；补充“聚焦→跨过至少一次 HUD 刷新→Enter／Space”的入口回归。当前竞技 DOM 场景手动添加名册行后立即点击，未覆盖此条件。

### B02 · P2 · 窗口不超过 800px 时没有竞技观战选人入口

- 位置：`dist/style.css:4`、`dist/index.html:40`、`dist/js/overlays.js:297`、`:361`。
- `@media(max-width:800px)` 将 `.roster-section` 隐藏，名册及其键盘入口同时消失。观战选人只绑定名册和首领榜单；竞技模式不显示首领榜单，也没有其他轮换目标按键。
- 因此在窄窗口死亡并点击“继续观战”后，只能跟随默认对象，不能主动选人，直到该对象死亡后自动回退。提示却仍要求点击右侧旅者或用 Enter／Space 切换。
- 证据为 CSS、HTML 结构及全部 `spectateId` 写入和事件绑定路径；本次未用浏览器截图验证。
- 建议：保留窄屏观战选择器，或提供上一位／下一位按钮和明确快捷键。项目虽不提供手机触控，桌面窄窗口仍会触发该问题。

### B03 · P3 · 小地图被 CSS 非等比拉伸

- 位置：`dist/index.html:38`、`dist/style.css:1`、`dist/js/renderer.js:106`。
- Canvas 缓冲区固定为 `224×170`，绘图内部使用等比缩放；CSS 随后将它拉到不同宽高比的容器内容区。
- 按 1440 CSS px 窗口下的声明尺寸计算：侧栏 264px，小地图框 162px 高，扣除两侧各 1px 边框和 5px 内边距后，显示为 `252×150px`。横向缩放 1.125，纵向约 0.882，圆形最终宽高比为 1.275，横向拉宽约 27.5%。
- 这影响地图距离、圆形风暴与视野框的视觉比例，不改变主战场碰撞或瞄准。数值来自 CSS 尺寸核算，未采集最终浏览器截图。
- 建议：统一显示框与缓冲区比例，或按显示尺寸更新缓冲区后重画并保留地图等比缩放。

### B04 · P3 · 无关指针抬起会中断持续攻击

- 位置：`dist/js/controls.js:14`、`:21`、`:24`。
- `pointerdown` 保存当前 `pointerId`，但全局 `pointerup` 只核对 `button===0`，`pointercancel` 也没有筛选指针。
- 使用真实 `createAttackInput()` 和 Node EventTarget 发送指针 1 按下、指针 2 抬起，结果从 `attackHeld=true` 变为 false，并释放指针 1 的捕获，尽管指针 1 从未抬起。
- 主要影响触屏电脑上的鼠标＋触摸或多触点输入，普通单鼠标流程通过现有测试；实际设备行为未在浏览器验证。
- 建议：按当前捕获指针筛选释放／取消事件，明确第二指针按下时的处理，并覆盖不同 pointerId 的回归。
